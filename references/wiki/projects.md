## 统一评估维度

真实需求、用户来源、补贴依赖、收入/费用、治理集中度、关联方、托管、合约安全、流动性、监管适配、退出路径。

## 生态分层

**基础协议层**是 TRON、TRX 与 TRC-20，回答共识、费用、治理和资产发行规则。**分发与托管层**是 HTX、钱包和其他入口，回答用户、上架、托管与牌照。**应用层**包括 JustLend、SunSwap、USDD 和 APENFT，回答实际使用、收入、治理和风险。**外部资本层**包括 TRON Inc. 与 WLFI 关系，必须用公司和交易文件识别。**AI 层**是 B.AI/BAIClaw，主张把模型、Agent 身份、支付和结算连接起来。

分层可以避免三种误写：代币在 TRON 发行不等于由 TRON 发行；TRON Inc. 与 TRON 协议名称相近但不是同一主体；HTX 顾问身份不等于平台所有权或每项运营决策。

## 核心项目详解

### TRON 与稳定币结算

S21 确认 DPoS 和 27 位超级代表的基本治理；S22 给出 2026 Q2 稳定币和投票权快照。分析优势时同时写低成本结算和大规模 USDT 使用，分析风险时写稳定币高度集中、治理集中度、地址去重和真实用途分类。

### BitTorrent 与 BTT

BitTorrent 收购提供成熟品牌、用户入口和去中心化分发叙事。评价整合不能只引用收购时用户规模，必须检查协议活跃、产品留存、代币用途、收入、团队变化和技术路线。BTT 的供应与链迁移另行记录，不与 BitTorrent 协议使用混为一谈。

### HTX

HTX 同时是交易入口、托管主体识别问题和制裁风险案例。研究顺序是运营主体、牌照、董事与受益所有权、储备与托管、顾问权限、制裁法域。S37 已确定英国和欧盟措施的具体边界，当前状态使用前重新核验。

### B.AI / BAIClaw

S42 的生态稿列出多模型路由、Agent 身份、x402 支付、交易与 TRON 结算，并描述 token 价差和交易费收入。事实层可写“产品方宣称具备”；产品成熟度必须由真实调用、付费用户、收入、安全审计、密钥权限、失败回滚和监管责任验证。

## 项目评价流程

先确定法律/协议主体，再确定产品用户和价值主张；随后读取代码与规则、链上数据、财务或储备、治理权限、关联交易、审计和事故；最后比较叙事与可观察结果。任何单一总量指标都不能代替完整评价。

## 数据结构

TVL、交易量、地址数和稳定币供应都必须注明日期、数据源、去重方法和统计口径。价格上涨不等于产品采用；链上交易也不自动等于独立用户需求。

## 已核心验证的产品事实

- S21：TRON 使用 DPoS；27 位当选 SR 按排程出块，网络参数可经提案改变。
- S22：2026 Q2 末，Messari 报告 TRON 稳定币市值约 892 亿美元、USDT 占比 98.5%，季度 USDT 转账约 2.1 万亿美元。这支持“稳定币结算已形成规模”，不证明所有转账都是支付、不证明去中心化程度，也不归因于单一人物。
- S25/S26：TRON Inc. 的法律控制在公开备案中归于 Weike Sun/Bravemorning；孙宇晨是独立承包顾问并通过 Black Anthem 持有少数表决权。品牌同名不能替代实体识别。
- S37：英国由 FCDO 指定 Huobi Global S.A.，OFSI 认为其拥有/控制的 HTX 交易所受英国金融制裁与资产冻结框架覆盖；欧盟另将 `HTX (HUOBI GLOBAL SA)` 列入 Annex XIX Part A，对欧盟经营者触发该框架下的交易禁令。两种法律效果不得混写，也改变了“法律主体与在线品牌完全无关”的可接受表述。
- S42：B.AI 公开宣称聚合多模型、Agent 身份与支付能力，并披露 API token 价差/交易费商业模式；目前仍缺独立代码审计、调用量、收入和事故数据。
