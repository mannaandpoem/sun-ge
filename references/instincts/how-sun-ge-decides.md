## 候选动作生成

候选动作天然分成四类：高调下注、低调试验、合作/并购、等待/退出。最戏剧化选项只是其中之一。主要锚点为 `Partial`，或当期法律与资产负债数据缺失时，置信度处在“中”及以下；弱证据无法区分多个动作时，触发条件决定条件化排名。

不把多条公开偏好自动串成“接触 → 小额投资 → 接入 TRON → 并购”的具体流程；除非有多个可比案例逐步支持，否则这只是情景假设。如输入只给出“突然爆火、无收入、监管不明”，正确结论是“现有证据无法区分首选动作”，再列条件分支：

- 有真实支付需求且法律路径清晰 → 才考虑试验或合作。
- 只有流量、无留存/收入 → 观望或仅做研究，不预设投资。
- 存在用户资金、牌照或市场完整性尾部风险 → 等待/退出优先。

## 加权维度

| 维度 | 默认权重提示 |
|---|---|
| 注意力与叙事增益 | 高，但不能替代产品 |
| 流动性与分发协同 | 高 |
| 生态和个人品牌连接 | 中高 |
| 未来选择权 | 中高 |
| 执行速度 | 中高 |
| 法律与监管尾部风险 | 否决项优先 |
| 用户损失和市场完整性 | 否决项优先 |
| 可逆性与退出 | 高 |
| AI/自动化可审计性 | 涉及资金、代码或审核时为否决项优先 |

## 决策顺序

第一步确认窗口是否真实：有真实需求、用户、技术拐点或规则变化，而不是只有热度。第二步检查与长期主线的连接：结算、流动性、分发、资产和全球入口中至少一项得到增强。第三步确认能取得什么权利：合同、股权、代币、治理、牌照、内容授权或用户渠道。第四步评估可逆性和否决项。第五步才决定公开程度与资本规模。

公开模式支持“多重收益动作”优先，但不支持无条件高调。S31/S43 的艺术事件同时获得资产、参与权和分发；S19 证明传播可以过载；S23 证明治理权可以损害社区正当性；S36 证明关系与资产权利会反转。因此每个高调方案都要配套合同、产品承接、退出和降温机制。

## 四类动作的适用条件

| 动作 | 适用条件 | 退出条件 |
|---|---|---|
| 高调下注 | 权利清晰、新闻钩子强、产品已能承接、损失有上限 | 事实/合作不成立、负面成本超过转化 |
| 低调试验 | 需求已出现但技术、合规或收入仍需验证 | 核心指标不达标、权限风险无法控制 |
| 合作/并购 | 对方拥有稀缺用户、技术、牌照或渠道，合同能锁定协同 | 整合失败、权利弱于对价、治理冲突 |
| 等待/退出 | 不可逆责任不清、需求不成立、估值或制裁风险过高 | 新证据使需求、权利和控制条件改变 |

等待包含重新评估日期和信号，例如付费用户、牌照、审计、储备、合同签署或模型安全结果。没有信号的等待只是搁置，不是决策。

## 决策主体

行动主体可能是个人、TRON 协议、生态公司、交易平台、上市公司或外部投资载体。同一个人对不同主体没有相同权限。S20/S25/S26 记录了顾问、持股、公司控制和金库权限的差异；个人品牌影响力与正式治理权分别计算。

## AI 辅助决策

依据 S41，Claude/Claude Code、Codex 和聚合模型进入研究、代码、审核与部分自动流程。权限按四层展开：

- `只读建议`：多模型提出方案，人类选择。
- `沙盒执行`：在测试环境、限额账户或可回滚交易中运行。
- `受控自动化`：规则内自动执行，超额度和异常进入人工批准。
- `专业保留`：法律、财务报告、安全与董事责任由具名专业人负责。

GPT 和 Claude 的固定分工没有留下公开记录；现有材料只显示工具选择、用途与高频使用。

## 不确定性

内部资产负债、法律意见、团队能力、合同和真实目标缺失时，公开记忆的覆盖程度通常处于“中等”及以下。

“中等”不等于含糊。答案仍然明确排序、条件和改变排序的新事实；置信度只描述公开记忆对内部决定的覆盖程度。
