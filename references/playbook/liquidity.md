# 流动性

## 核心命题

对加密产品，流动性不是后台指标，而是用户能否进入、交易、抵押、结算和退出的产品属性。

S08 的长期结算叙述、S21 的网络规则和 S22 的 2026 Q2 使用快照支持“结算与流动性是 TRON 公开主线”。S17/S24 同时要求对交易量、做市和市场完整性保持严格法律区分。

S39 在 2021 年已把区块链结算与 SWIFT/ACH/SEPA 对照；S42 又把流动性对象扩展到 AI Agent 购买模型 token、算力和服务。这是叙事连续性，不证明 B.AI 已形成真实流动性。

## 分析层次

- **市场流动性**：深度、滑点、价差和集中度。
- **资金流动性**：储备、赎回、期限和资产负债匹配。
- **网络流动性**：费用、吞吐、桥、钱包和稳定币可达性。
- **分发流动性**：交易平台、应用、支付入口和地域覆盖。
- **危机流动性**：挤兑、脱锚、攻击或提款高峰下的可用资金。
- **机器流动性**：Agent 的账户、预算、授权、支付失败、密钥与错误交易回滚（S42 的待验证新层）。

## 数据结构

交易量不等于有效深度；TVL 存在重复计算；做市和激励会制造短期活动；地址数不等于独立用户。

S22 的“稳定币市值、USDT 占比、季度转账额”是当期网络快照；不得将其直接翻译为实体支付量、个人业绩或产品无风险。

## 从入口到退出的完整路径

流动性分析必须覆盖用户全旅程：法币或外部资产如何进入；资产在哪条链和哪个平台交易；价格发现由哪些市场完成；资金如何跨应用流动；用户能否按明确条件赎回或退出。任何一段依赖单一托管人、单一稳定币、单一桥或少数治理者，都要单列集中度风险。

TRON 的公开优势叙事集中在低费用、高频稳定币转账和全球可达性。验证这套叙事时，读取 S21 的规则、S22 的当期网络数据，再补独立链上分析、交易所深度、真实费用和地域使用。网络转账额说明结算活动规模，不直接说明最终消费者数量、商业支付比例或协议利润。

## 六张检查表

| 层次 | 核心指标 | 典型误读 |
|---|---|---|
| 市场 | 深度、滑点、价差、集中度 | 把名义交易量当可成交深度 |
| 储备 | 资产质量、期限、托管、赎回 | 把储备总额当即时流动性 |
| 网络 | 费用、成功率、拥堵、桥依赖 | 把地址数当独立活跃用户 |
| 分发 | 钱包、平台、商户、地域 | 把上架当真实需求 |
| 危机 | 净流出、可用现金、暂停规则 | 只看正常时期数据 |
| Agent | 额度、密钥、失败支付、回滚 | 把自动执行当自治安全 |

## 危机压力测试

压力测试覆盖 24 小时集中提款、稳定币折价、主桥暂停、关键交易平台中断、制裁名单变化和密钥泄露。每个情景写出可立即动用的资产、用户通知、暂停权限、替代通道、恢复目标与损失承担者。没有压力测试的“高流动性”只描述正常市场。

## 价值捕获

流动性本身不是利润。必须说明谁从手续费、价差、质押、借贷、上架、托管或结算中获得收入，以及这些收入是否依赖补贴、关联交易或牛市价格。用户交易更频繁也不自动代表用户福利更高；成本、风险和退出能力必须同时衡量。
