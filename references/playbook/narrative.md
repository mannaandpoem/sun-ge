# 叙事

证据编号来自 [真实语料库](references/wiki/source-corpus.md)。

## 常见结构

- **大趋势**：数字金融、全球支付、去中心化或普惠。
- **具体载体**：TRON、稳定币、应用、平台或合作。
- **人物行动**：创始人亲自参与、购买、会面、发言或承诺。
- **可传播节点**：发布、里程碑、竞拍、活动或危机声明。
- **未来空间**：把当前动作解释为更大生态的一步。

## 好叙事的检验

一句话能否复述；是否有可核验事实；用户为何在意；产品如何承接；谁获得价值；什么会证伪；是否隐含未经授权的背书。

## 反模式

只讲宏大趋势、不解释产品；频繁换故事却不承认变化；用币价验证所有判断；把合作方曝光包装成认可；把不确定预测写成承诺。

## 两种叙事引擎

### 基础设施叙事

S08：从个人早期缺乏金融服务的经验进入，连接发展中市场、稳定币和 TRON 结算；结构是“个人经验 → 全球缺口 → 技术优越性 → 长期使命”。

S39 在 2021 年把 TRON 对标 SWIFT/ACH/SEPA；S42 在 2026 年把相同结构迁移到 AI Agent：`缺少账户/支付 → Agent 不能自治 → B.AI 宣称提供路由与结算 → TRON 被定位为底层`。连续性提高了“结算层”主线置信度，但 B.AI 的能力、性能和商业闭环仍是产品方主张。

### 事件/文学叙事

S11/S13：作品价值来自互联网和互动，购买者通过吃掉作品进入历史。S03：用账簿式细节写亲密关系，以“无限满足 → 第一次拒绝 → 空无”推动故事。结构是“极端具体 → 情绪克制 → 象征重复 → 行动转折 → 可争议结尾”。

文学引擎用真假余波制造传播，基础设施叙事用机制和数据建立确定性。真假余波在这里是刻意的：文末标注虚构，次日作者又称绝大多数属实（S41），两句话都由他自己说出，争论因此持续。这套双重定性可以研究，但涉及第三人的情节仍未获独立证实。

## 叙事的三层

**命题层**回答世界正在发生什么变化，例如全球支付迁移到区块链、AI Agent 需要账户与结算。**机制层**回答 TRON、稳定币或 B.AI 具体如何解决问题。**证据层**回答已有多少用户、交易、收入、安全记录和法律权利。三层必须同时出现，才能把愿景与事实分开。

孙宇晨的强传播文本通常先给极简命题，再用规模、最高级、金额和时间制造确定感，最后把个人行动放入历史趋势。数字负责现实感，未来时态负责方向，合作与控制负责把故事落到具体权利。

## 基础设施叙事的完整模板

`个人或用户痛点 → 现有系统成本 → 技术机制 → 当前采用证据 → 为什么本网络具备优势 → 尚未解决的约束 → 下一阶段里程碑`

S08/S39 可支持痛点与长期愿景；S21/S22 支持规则和当期网络快照；S42 支持 B.AI 产品方的 Agent 结算命题。B.AI 的调用、收入、安全和护城河必须用独立数据补证，不能由 TRON 的既有规模代替。

## 事件叙事的完整模板

`稀缺对象 → 取得参与权 → 一个可复述动作 → 跨圈层解释 → 与项目/身份连接 → 结果与反噬`

《Comedian》案例具备完整链路：竞拍取得作品权利，媒体反馈确认事件势能，公开食用形成单一动作，艺术/meme/加密三种语境合流，购买者进入作品历史。S19 作为反例提醒：事件不能无限放大，合作方意图和事实边界优先。

## 文学叙事的完整模板

S03 以账簿式精确细节建立现实感，以“不断满足”形成重复，以第一次拒绝制造转折，再用虚构声明翻转全文。它的写法是冷静数字、物质与情感错位、重复升级、克制结尾和真假余波；真实姓名本身也是标题冲击力和传播争论的一部分。

## 叙事校验表

1. 核心句能否准确复述且不夸大？
2. 每个数字和身份是否有日期与原始来源？
3. 产品机制是否具体到用户动作？
4. 价值由谁获得，风险由谁承担？
5. 哪项数据会推翻故事？
6. 合作方是否被误写成背书？
7. 文学、愿景、自述和事实是否明确分层？

## 叙事更新

当数据、监管或合作关系变化时，直接说明旧叙事的适用期、变化原因和新证据。不要删除历史承诺后假装从未发生。叙事迭代的可信度来自版本记录与可验证交付，而不是更换更宏大的关键词。
